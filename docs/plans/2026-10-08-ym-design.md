# ym — a background-agent dashboard for Cursor CLI

Status: approved design, spike done. Date: 2026-10-08.

## Goal

A `claude agents`-style harness for Cursor CLI (`agent`): see the status of every
session at a glance and jump into any of them instantly. Cursor first; the design
keeps Claude/Codex adapters possible later.

## Decisions

| Topic | Decision |
|---|---|
| Execution | Interactive `agent` sessions, each in its own tmux window |
| Substrate | Private tmux server (`tmux -L ym`) |
| Status source | Cursor hooks only (no screen reading) |
| Approvals | Handled by Cursor. "needs approval" status dropped from v1 (user runs `approvalMode: unrestricted`) |
| UI | TUI (TypeScript + Ink, compiled with Bun) |
| v1 features | new session, live preview, quick reply, rename/stop/remove, macOS notifications, import past Cursor chats |

## Architecture

- **tmux server** `tmux -L ym`, session `ym`. Window 0 is the dashboard; one window
  per agent. Enter → `select-window`; `Ctrl-g` (no prefix) returns to the dashboard
  from any window. `ym` from any terminal starts or attaches to the server.
- **State dir** `~/.ym/`
  - `sessions/<id>.json`: name, cwd, chatId, model, worktree, tmux window, createdAt.
  - `events/<id>.jsonl`: append-only status events.
- **Hook** `ym hook <event>`, registered in `~/.cursor/hooks.json` by `ym install`.
  No-op unless `YM_SESSION_ID` is set (only in ym-started windows). Records
  `beforeSubmitPrompt`, `preToolUse`, `postToolUse`, `stop`, `sessionEnd`.
  Every payload also carries `conversation_id` (= chatId) as a cross-check.

### Launch flow

1. `agent create-chat` → chatId (known before launch).
2. New tmux window: `agent --resume <chatId> [--model …] [-w <name>] "<prompt>"`
   with `YM_SESSION_ID` in the window environment.
3. Exited and imported sessions resume the same way in a new window.

### Status model

| Status | Signal |
|---|---|
| working | `beforeSubmitPrompt` / `preToolUse` / `postToolUse` |
| ready | `stop` (`status: "completed"`; other values → show as error) |
| exited | `sessionEnd` or tmux window gone |
| imported | past chat from `~/.cursor/chats`, not running |

Status is derived by replaying the event log, so dashboard restarts lose nothing.

## Dashboard

```
┌ ym ─ 5 sessions ─────────────────────────────┬ preview: fix-auth ───────┐
│ ◐ working         fix-auth   common-api   2m │ last ~40 lines, 1s tick  │
│ ◐ working         add-tests  lms-service  5m │                          │
│ ○ ready           docs-pass  niffler     12m │                          │
│ ✕ exited          spike      ym           1h │                          │
│ ⤓ imported        "pricing…" dev          2d │                          │
└──────────────────────────────────────────────┴──────────────────────────┘
 ⏎ jump  n new  r reply  e rename  x stop  d remove  i import  / filter  q quit
```

- Sort: ready → working → exited → imported; newest first.
- `⏎` jump (or resume if exited/imported). `n` new: prompt, cwd, model
  (from `agent models`), optional worktree.
- `r` one-line reply via `tmux send-keys -l <text>` + `Enter`, only when ready.
- `x` stop keeps the entry (resumable); `d` removes it.
- `i` import: browse `~/.cursor/chats/<hash>/<chatId>/`, grouped by cwd
  (`meta.json`). Title = `name` from `store.db` table `meta`, key `'0'`
  (hex-encoded JSON); fallback to first entry of `prompt_history.json`.
- Notifications via `osascript` on transition to ready or exited,
  only while the dashboard runs (no daemon in v1).

## Error handling

- Startup checks for `tmux`, `agent`, hook installed; missing → actionable message.
- `ym install` merges into `hooks.json` preserving existing hooks, backs it up;
  `ym uninstall` reverts. Never edits silently.
- Hook fails open: append one line, exit 0.
- Reconcile with `tmux list-windows` each tick: missing window → exited.
- Long silence in "working" → "working (stale?)".
- Append-only, single-line writes; truncated trailing line ignored.

## Spike results (Cursor CLI 2026.10.01)

- Hooks fire in the CLI and inherit `YM_SESSION_ID` from the tmux window env.
- Observed order per turn: `beforeSubmitPrompt` → `preToolUse` →
  `beforeShellExecution` → `afterShellExecution` → `postToolUse` →
  `afterAgentResponse` → `stop`. `sessionEnd` fires on exit. `sessionStart`
  did not fire for `--resume` launches (ym records creation itself).
- `agent create-chat` + `agent --resume <chatId> "<prompt>"` works.
- Reply via `tmux send-keys -l` then `Enter` works.
- Under `approvalMode: unrestricted`, neither `--auto-review` nor a hook
  returning `permission: "ask"` produces a prompt — hence approval status dropped.

## Implementation notes

- Build with `bun run build` (`scripts/build.ts`): Ink statically imports
  `react-devtools-core`, so the build stubs it out for `bun build --compile`.
- Text inputs use a small in-repo `LineInput` (readline keys: Ctrl-U/W/K/E, Home/End)
  instead of `ink-text-input`, which inserts control characters literally.
- Cursor stores chats under `~/.cursor/chats/<md5(realpath cwd)>/<chatId>/`, and a
  worktree chat moves to the worktree's hash, so resume always runs from the
  session's real path (the worktree path when one was used).
- Agent windows use `remain-on-exit`, so an exited agent's last screen stays
  visible in the preview until it is resumed or stopped.
- Filter tabs: All, Ready, Working (includes stale), Error, Exited, Imported,
  Archived. All excludes archived sessions; `a` toggles archive.

## Revision: prompt bar and live pane (2026-10-08)

- The preview is the real agent pane. The dashboard window is split: the Ink UI
  on the left (`dash.0`) and, on the right, either the selected agent's pane or a
  placeholder. Selecting a session runs `swap-pane` (placeholder ↔ agent), so the
  placeholder always sits either on the right or in the shown agent's own window.
  Agent panes are tagged with the pane option `@ym_id`; status uses panes, not
  window names.
- Enter on an empty bar focuses the agent pane (resuming it in place with
  `respawn-pane` if it exited). `Ctrl-g` returns to the UI pane.
- Always-on prompt bar: `@folder` tags with completion from session folders,
  Cursor chat folders, and `YM_ROOTS` (default `~/dev`, plus grandchildren under
  non-repo folders). The first folder is the workspace; the rest are `--add-dir`.
  No tag → last used folder.
- Actions moved to Ctrl keys (`^R` rename, `^X` stop, `^A` archive, `^D` delete,
  `^O` import, `^C` clear/detach); Tab cycles filters. Quick reply, the new-session
  form, model selection, and worktrees were removed.

## Revision: header and grouping (2026-10-08)

- Header modeled on `claude agents`: logo, `ym · <default model> · <folder>`,
  per-status counts, and the active grouping.
- Two tabs: Sessions and Archived (Tab switches). Status tabs were removed.
- Grouping (Shift-Tab cycles): by status (default; status headers with sessions
  nested), by folder (folder headers), by date (flat, most recent first).
- Interrupting a turn makes Cursor emit `stop: aborted` then `stop: error` ~15 ms
  later; an error stop within 2 s of an abort is ignored.

## Revision: action dialogs (2026-10-08)

- Rename, stop, archive/unarchive, and delete open centered dialogs instead of
  replacing the prompt bar or acting immediately.
- Dialogs exclusively capture keyboard input while open. Rename saves with
  Enter; confirmation dialogs default to Cancel and support arrow/Tab selection,
  Enter, Escape, and `y`/`n`.
- The dashboard remains visible but dimmed behind the dialog. Deleting clearly
  states that ym tracking data and the running pane are removed while the Cursor
  chat is preserved.

## Testing

1. **Unit** (`bun test`): status reducer on recorded logs, chat-import parsing,
   `hooks.json` merge.
2. **Integration**: throwaway tmux server + stub agent script that emits hook
   events.
3. **Manual**: one real Cursor session per status.
